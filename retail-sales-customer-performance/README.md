# Retail Sales & Customer Performance Dashboard

**Portfolio project | SQL · Python · Power BI · Excel**

An end-to-end retail analytics project that turns the UCI Online Retail transaction log into a reproducible sales and customer performance analysis. It demonstrates data cleaning, SQL analysis, customer segmentation, KPI design, business interpretation, and dashboard delivery.

## Business questions

- How did sales, order volume, and average order value change over time?
- Which customers account for the most observed revenue, and how recently did they purchase?
- How concentrated are sales by country?
- Which merchandise items generated the most recorded sales?
- What should a commercial team investigate next?

## Headline findings

- **£10,666,685** recorded line revenue over the source period
- **19,960** non-cancelled invoices and **5,588,376** units
- **4,338** customers with an ID; **2,845 (65.6%)** bought on at least two distinct invoices
- **United Kingdom** was the largest country market at **£9,025,222** (84.6% of recorded sales)
- The top merchandise item by recorded revenue was **REGENCY CAKESTAND 3 TIER** at **£174,485**
- Monthly revenue peaked in November 2011 at about **£1.51M**; December 2011 contains data only through December 9

These describe one retailer in 2010–2011; they are not estimates of current demand or causal campaign effects.

## Deliverables

- `src/analyze.py` downloads (or reads a cached copy of) the source, cleans transactions, builds summaries and charts, and writes a concise findings report.
- `sql/retail_performance.sql` contains DuckDB queries for sales, countries, products, repeat customers, and RFM segments.
- `powerbi/` contains Power Query import steps, a DAX measure starter pack, and setup guidance for a Power BI report.
- `Retail_Sales_Customer_Performance.xlsx` is an Excel dashboard with formula-linked KPIs, an editable monthly trend chart, customer segments, markets, products, and methodology notes.
- `results/` contains the derived summary tables and metric definitions used by the dashboard.
- `images/` contains the Python-generated charts used in the portfolio story.

## Reproduce the analysis

Python 3.10+ is recommended. From this project directory:

```bash
python -m pip install -r requirements.txt
python src/analyze.py
```

By default, the script downloads the official UCI dataset. To rerun without a network connection after downloading it once:

```bash
python src/analyze.py --offline
```

The source workbook is intentionally not committed. The pipeline fetches it from UCI or reads `data/Online Retail.xlsx` if cached locally. Generated row-level extracts are also excluded; only compact, derived outputs are tracked.

### SQL

The SQL uses DuckDB. Run it against `data/retail_sales_clean.csv` after running the Python pipeline, for example:

```bash
duckdb -c ".read sql/retail_performance.sql"
```

### Power BI

Open Power BI Desktop and load `data/retail_sales_clean.csv`. Follow `powerbi/README.md` to create the date table, add the supplied DAX measures, and build the report pages. The CSV is generated by the Python pipeline and is not checked in.

## Metric definitions and data quality

- **Recorded sales** are quantity × unit price for positive-quantity, positive-price lines on invoices whose invoice number does not start with `C`. Qualifying postage/service lines remain in total revenue. This is line revenue, not gross profit, cash receipts, or revenue net of every return adjustment.
- Rows with no `CustomerID` remain in sales, units, order, country, and product totals. They are excluded from customer counts, customer revenue analysis, and RFM segments.
- Cancellations, nonpositive quantities, nonpositive unit prices, and missing transaction dates are excluded from the positive-sales fact. Cleaning counts can overlap: cancellation records can also have nonpositive quantities.
- Repeat customers have at least two distinct invoices in the observed data window.
- RFM labels are heuristic groups derived from recency, frequency, and customer revenue. They are descriptive and should not be read as causal predictions.
- The merchandise leaderboard excludes service/adjustment codes `DOT`, `M`, `POST`, `D`, `C2`, `CRUK`, and `AMAZONFEE`; those qualifying line values remain in total sales.
